# 城市区块增量上传约定

生效日期：2026-10-29。用户要求：“以后上传就只上传修改的那个区块即可，做好备注”。

## 上传范围

后续城市更新只上传实际修改的区块模型，以及对应的更新说明、清单和必要验证记录。未修改区块沿用已保存的文件，不再重复上传全城 GLB、完整 Blender 工程或整城分卷包。用户另行要求完整交付时再提供完整版本。

一次改动涉及多个区块时，仅上传这些受影响区块。跨区道路、人行道、地形接缝、共享桥梁等需要同步修改时，将相关区块一并列入更新，并逐项注明原因；不能为了少传文件留下断路、错位或缺面。

区块文件较大时，只拆分该区块的交付文件，提供合并方式、分卷顺序及校验值，不重新打包整个城市。

## 基准与区块身份

初始完整基准为 [city_v13](../city_v13/README.md)，基准提交为 `0a2235ddb51c6cc5f29cf8c53b6bfa609cd11b3a`。完整交付包含 18 个区块；区块编号、名称和 GLB 文件名沿用 [districts_manifest.json](../../design/city/districts/districts_manifest.json)。其中 01–16 为陆地区块，17 为公共桥梁及引道，18 为公共海面与湖水。

区块编号和文件名保持稳定，保持米制、原世界坐标和轴向；导入根位置与旋转为零、缩放为 1，不重新居中。因修改导致对象跨区时，更新原归属区块和新归属区块，避免建筑或道路重复、遗漏。

## 每次交付的备注

后续增量放在 `delivery/city_updates/<update_id>/`，区块 GLB 放在其 `districts/` 子目录，并附 `README.md` 和 `manifest.json`。每次必须记录：

- 更新编号、日期、基准提交，以及所依赖的前一增量。
- 本次替换的区块编号、名称、文件名；哪些相邻或公共区块需要同时替换及原因。
- 具体改动内容，例如新增、删除、移动、缩放或复用的建筑，以及道路、人行道和地形的调整。
- 每个替换区块的旧文件 SHA256、新文件 SHA256、字节大小；分卷时记录各分卷及合并文件的校验值。
- 涉及建筑时的区块建筑数量变化、全城数量及预留地影响；相关模型预览和验证结果。
- 明确的替换步骤和任何尚未完成的事项。没有实际执行的检查不能标为通过。

清单要能解析出当前整套 18 个区块的来源：本次更新区块指向新文件，其余区块继续引用原基准或先前增量的路径、版本和校验值。元数据有变化时同步更新相关记录，但不重复附带未改动的模型。

## 替换与验证

先取得 v13 基准，再按依赖顺序应用增量；应用前核对待替换文件的版本和 SHA256。仅移除旧的对应区块，再导入新版本，避免叠加。不得把任意历史版本区块直接混用；整套完整 GLB 与分区模型也不要同时加载。

发布前重新导入修改区块，结合相邻未修改区块检查坐标、比例、贴图、重复及遗漏、道路与人行道连通、坡面和边界衔接；涉及桥梁时检查净空。核对未修改区块校验值保持不变。历史完整包及之前增量保留，用于回退。

本次仅记录后续上传约定，没有修改城市模型，也没有新增区块增量。
