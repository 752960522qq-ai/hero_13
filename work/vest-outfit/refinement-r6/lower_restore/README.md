# R6 原始下身恢复与保形绑定

最终候选已保存为 `lower_candidate.blend`。供主线程合并的接口为 `apply_lower.py` 中 `apply_lower()`，输入为本目录 `lower_patch.npz`。函数可重复执行，使用绝对坐标、骨骼头尾和曲线值，不会累加变换。主线程应在R5继承场景中调用；候选未包含并排参考人体。

## 下身源形

原始处理后源顶点仅统一放大1.7倍，再平移 `[-.00023407833465015, -.1259081221330608, -.00964825950517234]`。身体源Z≤.60且源absX<.155区域完全恢复原形；源Z .60–.65平滑接回R5躯干。源absX≥.155排除手部，头、颈与手臂不修改。两只鞋按各自 `source_vertex_id` 恢复到同一个全身等比坐标系，只改变整体位置、不改变鞋体内部几何关系。下身恢复区域位置最大浮点残差约5.61e-8m。

原始源法线通过稳定面/顶点编号恢复，共183159个面角法线，不保留旧RBF表面的失真法线。整体不再纵向拉长小腿或压扁肌腹。

## 骨骼与蒙皮

使用源解剖点定位，不使用GLB任意指向的骨尾作为解剖端点。左侧髋/膝/踝中心分别约 `[.093266,.011792,.928752]`、`[.084766,-.000108,.593852]`、`[.106555,.021820,.319130]`；右侧对应约 `[-.093734,.011792,.928752]`、`[-.085234,-.000108,.593852]`、`[-.111625,.023105,.319450]`。踝中心取原源鞋腿连接环质心下15mm。38根腿部主骨、辅助骨及足部子骨按解剖段平滑平移，方向与层级保持。

小腿肌腹源Z .222–.345采用单侧tibia100%；脚踝混合仅在原鞋腿环到源Z .222的短带；膝部源Z .345–.375混合tibia/femur。大腿肌腹主要由femur100%驱动，源Z .50–.56平滑接髋，源Z .54–.585恢复原骨盆绑定。每侧100个鞋腿共享顶点仍由ankle100%驱动，保证动态接边重合。

## 高跟鞋踝部动作适配

原赤脚动作的踝转动会在短踝带上挤出横向折痕。为适配刚性厚底高跟鞋，Idle/Walk/Run左右踝骨局部四元数使用小角度15%衰减与3度tanh平滑上限；保留旋转方向、关键帧时刻、关键帧句柄相对形状和循环端点一致性。仅改24条踝骨四元数曲线，髋、膝、躯干、手臂和手指动作曲线均不改。

## 必要局部复看

Rest/Idle/Walk/Run各选同一35%时刻的正侧面。最终`Idle_front.png`、`Walk_front.png`、`Run_front.png`中此前小腿下段横向挤压带已消除，原模型的肌腹轮廓保留。原膝窝弯曲褶皱仍保留，未重制膝部。

`lower_report.json`记录恢复误差、关节目标、肌腹局部边长和鞋体刚性证据。选定小腿核心边群在四姿态中的最小/最大长度比约0.99997–1.00003，鞋边长比约1，差异为微小边上的浮点误差。没有执行无关全套手指测试或浏览器检查，也没有部署。
