## 导入与拼接

1. 每个 GLB 都已采用城市世界坐标。导入后的根节点保持位置 `(0,0,0)`、旋转为零、缩放为一；不要分别居中，也不要再加区块偏移。1 单位 = 1 m。
2. GLB 为 X 向东、Y 向上、-Z 向北；Blender 源场景为 X 向东、Y 向北、Z 向上。导入器的轴转换正常使用即可。
3. 公共文件 `17_shared_bridges.glb`、`18_shared_water.glb` 可常驻，其余陆地区块可分别加载。全部 18 个 GLB 一起加载可重组完整城市。
4. 完整城市 GLB 与这套区块内容重复，使用时选择其中一套。区块内已包含所属建筑、基座、路面、人行道、地形及其他物件。

建筑及对应基座作为整体分配；大型地面网格按完整三角面分配，保留原世界坐标、UV、顶点色和法线。完整建筑或边界面片可能跨出逻辑区域，因此相邻区块包围盒可重叠；这不等于重复面。准确的 Blender / GLB 坐标包围盒、源建筑实例及字节大小见 `districts_manifest.json`。

## 验证结果与使用范围

18 个 GLB 均已独立重新导入，合计 2,276,376 个三角面，与完整场景一致。源面完整分配且没有重复；各区顶点世界坐标比对最大误差 0；11 栋素材建筑各出现一次，嵌入贴图字节与完整模型一致。见 `districts_validation.json`，源面分配明细见 `partition_audit.json.gz`。

此包交付模型分区，未在游戏中配置动态加载、碰撞或寻路，也未测试目标设备帧率。建筑和基座的几何适配检查不代替游戏运行验证。完整可编辑 Blender 工程另行提供，包含原始输入素材和重建脚本。
